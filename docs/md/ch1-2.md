本系统包含用户、场地、分类、预约、评价五个实体。用户与场地两个实体之间通过"预约""评价"两个联系实体建立多对多关联，分类与场地之间为一对多关联，系统 E-R 图如图 1-2 所示。

图1-2 系统 E-R 图

根据 E-R 图将概念模型转换为 5 张数据表，均使用 utf8mb4 字符集，表之间通过外键保证参照完整性。各表结构如下：

**（1）用户表 user**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT | 用户ID，主键，自增 |
| username | VARCHAR(50) | 用户名，唯一非空 |
| password | VARCHAR(100) | 密码 |
| real_name | VARCHAR(50) | 真实姓名 |
| phone | VARCHAR(20) | 手机号 |
| role | VARCHAR(20) | 角色：USER 普通用户 / ADMIN 管理员 |
| status | TINYINT | 状态：1 正常 / 0 禁用 |
| create_time | DATETIME | 注册时间 |

**（2）场地分类表 category**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT | 分类ID，主键，自增 |
| name | VARCHAR(50) | 分类名称 |
| description | VARCHAR(200) | 分类描述 |
| sort_order | INT | 排序号 |
| create_time | DATETIME | 创建时间 |

**（3）场地表 venue**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT | 场地ID，主键，自增 |
| name | VARCHAR(100) | 场地名称 |
| category_id | BIGINT | 所属分类ID，外键→category(id) |
| location | VARCHAR(200) | 场地位置 |
| capacity | INT | 容纳人数 |
| price_per_hour | DECIMAL(10,2) | 每小时价格（元） |
| description | TEXT | 场地描述 |
| status | TINYINT | 状态：1 开放 / 0 关闭 |
| create_time | DATETIME | 创建时间 |

**（4）预约表 reservation**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT | 预约ID，主键，自增 |
| order_no | VARCHAR(32) | 预约单号，唯一 |
| user_id | BIGINT | 用户ID，外键→user(id) |
| venue_id | BIGINT | 场地ID，外键→venue(id) |
| start_time | DATETIME | 预约开始时间 |
| end_time | DATETIME | 预约结束时间 |
| total_price | DECIMAL(10,2) | 总价（元），按半小时进位计算 |
| status | VARCHAR(20) | 状态：PENDING/CONFIRMED/CANCELLED/FINISHED |
| remark | VARCHAR(200) | 备注 |
| create_time | DATETIME | 预约提交时间 |

**（5）评价表 review**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT | 评价ID，主键，自增 |
| user_id | BIGINT | 用户ID，外键→user(id) |
| venue_id | BIGINT | 场地ID，外键→venue(id) |
| reservation_id | BIGINT | 关联预约ID，外键→reservation(id) |
| rating | TINYINT | 评分（1~5） |
| content | VARCHAR(500) | 评价内容 |
| create_time | DATETIME | 评价时间 |

其中预约表与评价表是用户和场地两个实体多对多联系的物化：一个用户可以预约/评价多个场地，一个场地也可被多个用户预约/评价；场地表的 category_id 实现分类到场地的 1:n 联系。
