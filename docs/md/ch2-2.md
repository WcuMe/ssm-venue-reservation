用户登录由 UserController 接收表单参数，调用 UserService 校验账号密码，校验通过后写入 HttpSession；权限控制由 LoginInterceptor 拦截器统一完成，核心代码如下：

```java
public class LoginInterceptor implements HandlerInterceptor {

    @Override
    public boolean preHandle(HttpServletRequest request, HttpServletResponse response,
                             Object handler) throws Exception {
        HttpSession session = request.getSession();
        User loginUser = (User) session.getAttribute("loginUser");

        if (loginUser == null) {
            response.sendRedirect(request.getContextPath() + "/login?redirect="
                    + URLEncoder.encode(request.getRequestURI(), "UTF-8"));
            return false;
        }
        // 管理端请求需要 ADMIN 角色
        String uri = request.getRequestURI();
        if (uri.contains("/admin/") && !"ADMIN".equals(loginUser.getRole())) {
            response.sendError(403, "无权限访问管理后台");
            return false;
        }
        return true;
    }
}
```

逻辑说明：拦截器在 spring-mvc.xml 中注册，拦截 /admin/**、/my/** 及预约、评价等受保护请求。preHandle 方法先从 Session 中取出登录用户，未登录则重定向到登录页并携带 redirect 参数（登录后可跳回原页面）；若访问的是 /admin/ 开头的管理端地址，还会校验角色是否为 ADMIN，普通用户直接返回 403。通过拦截器把权限判断集中在一处，避免在每个 Controller 中重复编写。

**2.2.2 场地预约（时间冲突校验与费用计算）核心代码及说明**

预约是本系统最核心的业务，由 ReservationServiceImpl.create 方法完成，依次执行"时间合法性校验 → 场地状态校验 → 冲突校验 → 费用计算 → 生成单号入库"五个步骤：

```java
@Service
@Transactional
public class ReservationServiceImpl implements ReservationService {

    @Override
    public Reservation create(Long userId, Long venueId, String startTimeStr,
                              String endTimeStr, String remark) throws Exception {
        // 1. 时间解析与合法性校验
        Date startTime = SDF.parse(startTimeStr);
        Date endTime = SDF.parse(endTimeStr);
        if (!endTime.after(startTime)) {
            throw new Exception("结束时间必须晚于开始时间");
        }
        // 2. 场地校验
        Venue venue = venueMapper.selectById(venueId);
        if (venue == null || venue.getStatus() != 1) {
            throw new Exception("该场地当前未开放预约");
        }
        // 3. 时间段冲突校验
        List<Reservation> conflicts =
                reservationMapper.selectConflicts(venueId, startTime, endTime);
        if (!conflicts.isEmpty()) {
            throw new Exception("预约失败：该时间段已被占用（与预约单 "
                    + conflicts.get(0).getOrderNo() + " 冲突）");
        }
        // 4. 计算总价（不足半小时按半小时计）
        double hours = (endTime.getTime() - startTime.getTime()) / (1000.0 * 60 * 60);
        double halfHours = Math.ceil(hours * 2) / 2;
        BigDecimal totalPrice = venue.getPricePerHour()
                .multiply(BigDecimal.valueOf(halfHours))
                .setScale(2, BigDecimal.ROUND_HALF_UP);
        // 5. 生成预约单号并入库
        Reservation reservation = new Reservation();
        reservation.setOrderNo(generateOrderNo());
        reservation.setTotalPrice(totalPrice);
        reservation.setStatus(Reservation.STATUS_PENDING);
        reservationMapper.insert(reservation);
        return reservation;
    }
}
```

冲突判断的核心 SQL 在 ReservationMapper.xml 中，利用"两个时间段存在交集 ⟺ 已有开始 < 新结束 且 已有结束 > 新开始"的区间重叠判定条件，且只统计未取消（待确认/已确认）的预约：

```xml
<!-- 时间段冲突：与 [startTime, endTime) 存在交集且未取消 -->
<select id="selectConflicts" resultMap="BaseResultMap">
    SELECT r.*, u.username, v.name AS venue_name
    FROM reservation r
    LEFT JOIN user u ON r.user_id = u.id
    LEFT JOIN venue v ON r.venue_id = v.id
    WHERE r.venue_id = #{venueId}
      AND r.status IN ('PENDING', 'CONFIRMED')
      AND r.start_time &lt; #{endTime}
      AND r.end_time &gt; #{startTime}
</select>
```

逻辑说明：整个 create 方法标注了 @Transactional，由 Spring 声明式事务保证"冲突检查 + 写入"的原子性，任何一步校验失败抛出异常即整体回滚；费用计算使用 BigDecimal 避免浮点误差，通过 Math.ceil(hours*2)/2 实现"不足半小时按半小时计"的进位规则；预约单号由"R + 14 位时间戳 + 4 位随机数"组成，保证唯一。

**2.2.3 场地多条件查询与评分统计核心代码及说明**

前台首页的场地列表需要同时支持"按分类筛选 + 关键词模糊搜索"，并且每个场地要带出平均评分和评价数。该功能在 VenueMapper.xml 中通过 MyBatis 动态 SQL 与聚合子查询实现：

```xml
<sql id="baseSelect">
    SELECT v.*, c.name AS category_name,
           IFNULL(r.avg_rating, 0) AS avg_rating,
           IFNULL(r.review_count, 0) AS review_count
    FROM venue v
    LEFT JOIN category c ON v.category_id = c.id
    LEFT JOIN (SELECT venue_id, AVG(rating) AS avg_rating, COUNT(*) AS review_count
               FROM review GROUP BY venue_id) r ON v.id = r.venue_id
</sql>

<select id="selectList" resultMap="BaseResultMap">
    <include refid="baseSelect"/>
    <where>
        <if test="categoryId != null">AND v.category_id = #{categoryId}</if>
        <if test="keyword != null and keyword != ''">
            AND v.name LIKE CONCAT('%', #{keyword}, '%')
        </if>
        AND v.status = 1
    </where>
    ORDER BY v.id
</select>
```

逻辑说明：`<where>` 标签自动处理 AND/OR 前缀，配合 `<if>` 判断实现参数可选的多条件组合查询——用户不选分类、不填关键词时查询全部开放场地，选择任一条件则动态拼接；平均评分通过 LEFT JOIN 一个按场地分组的 AVG 聚合子查询获得，使用 IFNULL 保证无评价的场地显示 0 分，避免空指针；模糊查询使用 CONCAT 拼接 % 通配符，参数一律通过 #{} 预编译占位，防止 SQL 注入。
